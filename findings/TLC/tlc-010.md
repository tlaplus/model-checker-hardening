# An evaluation error while checking liveness escapes as TLC error 1000

## Summary

When a formula that TLC checks during state exploration raises an evaluation
error, TLC reports "TLC threw an unexpected exception", or only "The behavior up
to this point is:" with no diagnostic at all, and exits with status 255.
`TLC.process()` returns the general error 1000. This happens for `[]<>P`, `<>[]P`,
`[]<><<A>>_v`, and `WF_v(A)` or `SF_v(A)`, whether the fairness condition is the
property or a conjunct of the specification. The same failing expression under
`[]`, or in an invariant, is reported as an ordinary evaluation error with exit 75.

Observed with tla2tools 1.8.0-SNAPSHOT (Maven snapshot
`1.8.0-20260912.025952-68`). This differs from [tlc-009](tlc-009.md), where the
error escapes before TLC computes any initial state, and from
[tlc-008](tlc-008.md), where an error in `<>P` or `~>` exits 0. Here the error
occurs after the initial states are computed.

## Reproduction

`FuzzInput.tla`:

```tla
---- MODULE FuzzInput ----
EXTENDS Integers
VARIABLE x
Init == x = 0
Next == (x < 2 /\ x' = x + 1) \/ UNCHANGED x
Spec == Init /\ [][Next]_x
Prop == WF_x(x' = <<>>[x + 1])
====
```

`FuzzInput.cfg`:

```text
SPECIFICATION Spec
PROPERTY Prop
```

```sh
java -cp tla2tools.jar tlc2.TLC -deadlock -noGenerateSpecTE -config FuzzInput FuzzInput
echo $?
```

```text
Implied-temporal checking--satisfiability problem has 1 branches.
Computing initial states...
Finished computing initial states: 1 distinct state generated at 2026-09-15 09:39:46.
Error: The behavior up to this point is:
State 1: <Initial predicate>
x = 0

3 states generated, 2 distinct states found, 1 states left on queue.
255
```

The out-of-bounds access `<<>>[1]` is not mentioned. Replacing `Prop`, or adding a
conjunct to `Spec`, with the same configuration:

| Formula | TLC prints | Exit status |
| --- | --- | ---: |
| `Prop == WF_x(x' = <<>>[x + 1])` | only the behavior | 255 |
| `Prop == SF_x(x' = <<>>[x + 1])` | only the behavior | 255 |
| `Prop == []<>(<<>>[x + 1] = 1)` | only the behavior | 255 |
| `Prop == <>[](<<>>[x + 1] = 1)` | only the behavior | 255 |
| `Prop == []<><<x' = <<>>[x + 1]>>_x` | only the behavior | 255 |
| `Prop == []<>(ENABLED (x' = <<>>[x + 1]))` | only the behavior | 255 |
| `Spec == ... /\ WF_x(x' = <<>>[x + 1])`, `Prop == []<>(x = 2)` | only the behavior | 255 |
| `Prop == WF_x(x' = (CHOOSE k \in {} : TRUE))` | unexpected `RuntimeException` wrapping the `CHOOSE` diagnostic | 255 |
| `Prop == [](ENABLED (x' = <<>>[x + 1]))` | `Attempted to access index 1 of tuple` | 75 |

An action that does not determine every primed variable of the subscript takes
the same path. `WF_x(x' > x)` reports an unexpected `RuntimeException`, "In
evaluation, the identifier x is either undefined or not an operator", and exits
255, while `WF_x(x' = x + 1)` is checked.

Errors that TLC raises from a standard module, such as `Head(<<>>)`, carry their
own error code and also exit 255; [tlc-002](tlc-002.md) describes that mapping.

## Corpus evidence

The `module` corpus22, generated with the `action` and `temporal` categories,
has 56 TLC crashes of this kind. Each has the `Implied-temporal checking` line
and reports error 1000 after `Finished computing initial states`. In 54 the
property or `Spec` contains `WF` or `SF`; one property is `<>[]P`, and one is
`P ~> ENABLED A`. In 50 the exception wraps the diagnostic: a function applied outside its domain, an out-of-bounds tuple index,
`CHOOSE` without a witness, a `CASE` without a matching arm, a non-enumerable
quantifier bound, an undefined primed variable, or an action that does not
specify a primed variable. The innermost reported position is in `Prop` for 45
of them and in `Fairness` for 5; in `358f84eb`, for example, the property is
`var2 ~> var2` and the failing expression is in the fairness conjunct of
`Spec`. In the remaining 6 only the behavior is printed, with no position.

Before this finding, the triager assigned 19 of these crashes to
[tlc-001](tlc-001.md), whose signature matched any function-domain
`RuntimeException` under error 1000. The reported position of each of the 19 is
in `Prop` or `Fairness`.

## Expected behavior

TLC reports the evaluation error with its diagnostic and location, and a failure
exit status, as it does for the same expression under `[]`.

## Impact

Automated consumers classify the run as a TLC crash instead of a failing
specification. When no diagnostic is printed, a user cannot tell what failed.
