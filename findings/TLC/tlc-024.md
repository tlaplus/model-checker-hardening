# An evaluation error in another successor cuts the trace of an invariant violation short

## Summary

When TLC finds a successor state that violates an invariant, it prints the trace by
generating the successors of each state again and matching the next state's fingerprint.
For the last step, it generates every successor of the action that produced the violating
state. If another branch of that action raises an evaluation error, the exception escapes
trace printing before the violating state is printed. TLC prints "Invariant Inv is
violated", the trace without its last state, and "TLC threw an unexpected exception" with
the other branch's error. It exits with status 12, the status of the violation.

The printed trace ends in a state that satisfies the invariant. TLC found that branch's
error only because it generated the successors again; while checking, it stopped at the
violation first.

This is [tlaplus/tlaplus#810](https://github.com/tlaplus/tlaplus/issues/810), "TLC will
leave last step off invariant error trace if it also triggers an exception", open since
2023. This finding adds the cause and the consumers it misleads.

Observed with TLC 2026.11.19 (`bc1b506`, the head of tlaplus/tlaplus `master` on
2026-11-25), on OpenJDK 25 for Linux aarch64. FuzzTLA `218ef666` found it.

## Reproduction

`Repro.tla`:

```tla
---- MODULE Repro ----
EXTENDS Integers
VARIABLE x
Init == x = 0
Next == TRUE /\ (x' = 1 \/ x' = CHOOSE y \in {} : TRUE)
Inv == x = 0
====
```

`Repro.cfg`:

```text
INIT Init
NEXT Next
INVARIANT Inv
```

```sh
java -cp tla2tools.jar tlc2.TLC -workers 1 -deadlock -noGenerateSpecTE -nowarning Repro.tla
echo $?
```

```text
Error: Invariant Inv is violated.
Error: The behavior up to this point is:
State 1: <Initial predicate>
x = 0

Error: TLC threw an unexpected exception.
This was probably caused by an error in the spec or model.
See the User Output or TLC Console for clues to what happened.
The exception was a java.lang.RuntimeException
: Attempted to compute the value of an expression of form
CHOOSE x \in S: P, but no element of S satisfied P.
line 5, col 33 to line 5, col 54 of module Repro
...
12
```

State 2, `x = 1`, which violates `Inv`, is missing. Each change below makes the report
consistent:

| Change to `Repro` | Report | Exit status |
| --- | --- | ---: |
| none | violation, trace without state 2, then the `CHOOSE` error | 12 |
| `Next == x' = 1 \/ x' = CHOOSE y \in {} : TRUE` | violation, complete trace | 12 |
| the two disjuncts swapped | `CHOOSE` error and its trace | 75 |
| `Inv == TRUE` | `CHOOSE` error and its trace | 75 |

The second row is the action condition. TLC splits a top-level disjunction of `Next` into
separate actions, and it stops generating the successors for the trace at the first
action that yields the violating state. A disjunction inside a conjunct belongs to one
action, whose successors TLC generates all at once.

## Expected behavior

TLC should print the complete trace of the violation it found. The trace generation could
stop at the first matching successor rather than generate them all, or catch an
evaluation error in another branch and go on. If it cannot recover the state, it should
say that the trace is incomplete, not print a trace that ends in a state satisfying the
invariant.

## Impact

- **Users** get a counterexample whose last state satisfies the invariant, followed by an
  error in a branch that the checked behavior never takes.
- **Consumers that classify by exit status** see an invariant violation, but its trace
  does not violate the invariant. FuzzTLA recorded such traces as counterexamples and
  replayed them ([ADR 0034](../../docs/decisions/0034-counterexample-replay.md)), and
  every checker refuted them.

The defect needs a partial term in a branch of the violating action, which TLC evaluates
only when it generates that action's successors. Generated specifications have them
often; hand-written ones that rely on TLC's left-to-right evaluation to guard a partial
term, as in `S = {} \/ P(CHOOSE x \in S : TRUE)`, have them too.

## Root cause

Line numbers are from `bc1b506`.

- `TLCTrace.printTrace(s1, s2)` (`tlc2/tool/TLCTrace.java`) prints the prefix and `s1`,
  then reconstructs `s2` with `this.tool.getState(s2, s1)` (line 430).
- `Tool.getState(TLCState s1, TLCState s)` (`tlc2/tool/impl/Tool.java`, lines 3805–3830)
  loops over the actions and, for each, calls `this.getNextStates(curAction, s)` (line
  3809), which generates every successor of the action before the loop compares any of
  them with `s1`.
- The loop catches a `TLCRuntimeException` only around the comparison `s1.equals(state)`,
  for incomparable values ([tlaplus/tlaplus#743](https://github.com/tlaplus/tlaplus/issues/743)).
  An evaluation error raised by `getNextStates` escapes `printTrace`, and the caller
  reports it as an unexpected exception. The violation's exit status is already set.

[`tlc-021`](tlc-021.md) reaches the same reconstruction from a failing successor, and
[`tlc-007`](tlc-007.md) from an invariant whose evaluation fails.

## How it was found

corpus90 replays every counterexample as an input of its own
([ADR 0034](../../docs/decisions/0034-counterexample-replay.md)). TLC refuted six of its
own traces, all with one state and the ending "violates Inv", whose state satisfies
`Inv`. The parents are `7c39174f1f55`, `722721b18185`, `ccc01e90cd0a`, `2935bffe89e1`,
`92491e6da590` and `a55a23099c70`. On each, TLC reports a counterexample of 0
transitions and Apalache one of 1 transition. Rerunning TLC on the parents prints the
truncated trace, followed by a `CHOOSE` without a witness, a function applied outside
its domain, a `CASE` without a true guard, or a tuple index out of range.

In `7c39174f1f55`, `Next` applies the recursion library's
`SetAllPositive(S) == S = {} \/ (LET x == Any(S) IN x > 0 /\ SetAllPositive(S \ {x}))`,
whose second disjunct TLC evaluates even when `S = {}`.

FuzzTLA now records such a counterexample without a trace: `TlcTraceRecorder` drops the
trace when TLC reports an unexpected exception (1000) after a violation.

## Signature

None. `signatures/all-defects.toml` lists this finding as uncovered. Any partial term in a
branch of an action can trigger it, and the shapes are those of the conformance documents
on partial terms.
