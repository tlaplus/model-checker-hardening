# An evaluation error in an eventuality of the initial state exits with status 0

## Summary

When a temporal property's eventuality (`<>P`, or either side of `~>`) raises
an evaluation error in the initial state, TLC prints the error and then ends model
checking with exit status 0. `TLC.process()` returns 0 as well. The run stops
with states left on the queue, and no property is checked. A consumer that reads
the exit status records a negative specification as a successful check.

The status also hides an invariant violation. When the initial state violates the
invariant, TLC prints `Invariant Inv is violated by the initial state` after the
evaluation error and still exits 0, so a counterexample TLC itself reported is
recorded as a pass.

Observed with tla2tools 1.8.0-SNAPSHOT (Maven snapshot
`1.8.0-20260912.025952-68`). The same error elsewhere is reported with an
evaluation-failure status: exit 75 in the initial predicate or under `[]`, and
exit 76 when a `[]` property fails in a later state.

## Reproduction

`FuzzInput.tla`:

```tla
---- MODULE FuzzInput ----
EXTENDS Integers, Sequences
VARIABLE x
Init == x = 0
Next == UNCHANGED x
Spec == Init /\ [][Next]_x
Prop == <>(Head(<<>>) = x)
====
```

`FuzzInput.cfg`:

```text
SPECIFICATION Spec
PROPERTY Prop
```

```sh
java -cp tla2tools.jar tlc2.TLC -deadlock -noGenerateSpecTE -config FuzzInput FuzzInput
echo $?
```

```text
Implied-temporal checking--satisfiability problem has 1 branches.
Computing initial states...
Error: Attempted to apply Head to the empty sequence.
1 states generated, 1 distinct states found, 1 states left on queue.
The depth of the complete state graph search is 1.
Finished in 00s at (2026-09-14 12:03:22)
0
```

Calling `new TLC()`, `handleParameters` with the same arguments and `process()`
returns 0, which `EC.ExitStatus.errorConstantToExitStatus` maps to 0.

The status depends on the temporal operator around the same failing predicate:

| `Prop` | Exit status |
| --- | ---: |
| `<>(Head(<<>>) = x)` | 0 |
| `(x = 0) ~> (Head(<<>>) = x)` | 0 |
| `<>(x \div 0 = 1)` | 0 |
| `<>((CHOOSE k \in {} : TRUE) = x)` | 0 |
| `((x \div 0) = 1) ~> FALSE` | 0 |
| `[](Head(<<>>) = x)` | 75 |

### A masked invariant violation

Adding `Inv == x # 0`, which the initial state violates, with `INVARIANT Inv` in the
configuration:

| `Prop` | TLC prints | Exit status |
| --- | --- | ---: |
| `TRUE` | `Invariant Inv is violated by the initial state` | 12 |
| `<>((x \div 0) = 1)` | `The second argument of \div is 0`, then `Invariant Inv is violated by the initial state` | 0 |
| `((x \div 0) = 1) ~> FALSE` | the same two errors | 0 |
| `(x = 0) ~> ((x \div 0) = 1)` | the same two errors | 0 |
| `[]((x \div 0) = 1)` | `Invariant Inv is violated by the initial state` | 12 |

The corpus20 input
[`016a5be5...`](../../corpus20/03aggregator-fail/016a5be5d02d62185477a16f604f0bfed50cdb0dff0eb843617a8226de78025b.cbor)
has this shape: its property is `P ~> FALSE`, where `P` reaches `% 0`. TLC printed
both errors and was recorded as a pass, while Apalache reported the invariant
violation. The run used TLC2 version 2026.09.12.025210 (rev `867aefb`).

### An eventuality failing in a later state

When the eventuality fails only in a later state, as in
`<>(x = 1 /\ Head(<<>>) = x)` with `Next == (x < 2 /\ x' = x + 1) \/ UNCHANGED x`,
TLC reports the behavior and exits 255; that status is the module-constant
mapping described in [tlc-002](tlc-002.md).

## Expected behavior

TLC reports the evaluation error with a failure exit status, as it does for the
same predicate under `[]` (exit 75).

## Impact

Automated workflows that classify TLC runs by exit status, including this
repository's conformance aggregator, record the specification as passing, even
when TLC also found an invariant violation. The TLC-versus-Apalache comparison
then attributes the difference to Apalache.
The fuzzing workflow generates such properties once the `temporal` generator
category is enabled.
