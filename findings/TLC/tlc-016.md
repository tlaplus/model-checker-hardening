# The `IsInjective` override of the Community Modules rejects records and unevaluated functions

## Summary

The Java override of `Functions!IsInjective` in the TLA+ Community Modules
accepts only some of TLC's function representations. It fails with
`The argument of IsInjective should be a function, but instead it is:` on two
kinds of function:

- a record, such as `IsInjective([a |-> 1, b |-> 2])`, in every context;
- a function constructor `[x \in S |-> e]` whose domain is not `1..n` when
  TLC has not yet turned it into an explicit function. This happens, for
  example, when it is an argument inside the function part of an application,
  as in `(IF IsInjective([b \in BOOLEAN |-> FALSE]) THEN <<1>> ELSE <<2>>)[1]`.

The TLA<sup>+</sup> definition,
`IsInjective(f) == \A a,b \in DOMAIN f : f[a] = f[b] => a = b`, is defined for
both and evaluates to `FALSE` in these examples. Apalache uses that definition.

Observed with CommunityModules release `202609120237` (commit `9aae8ea`), tla2tools
1.8.0-SNAPSHOT (Maven snapshot `1.8.0-20260917.033119-76`, tlaplus/tlaplus
commit `142d0ba`), FuzzTLA `a13a4d1`, and Apalache 0.62.2 (build `f0dec98`).

## Reproduction

`FuzzInput.tla`, run with `CommunityModules.jar` on the class path:

```tla
---- MODULE FuzzInput ----
EXTENDS Naturals
F == INSTANCE Functions
VARIABLE x
Init == x = 0
Next == x' = (IF F!IsInjective([b \in {TRUE, FALSE} |-> FALSE]) THEN <<1>> ELSE <<2>>)[1]
Spec == Init /\ [][Next]_x
====
```

`FuzzInput.cfg`:

```text
SPECIFICATION Spec
```

```sh
java -cp tla2tools.jar:CommunityModules.jar tlc2.TLC \
  -workers 1 -deadlock -noGenerateSpecTE -config FuzzInput FuzzInput
```

```text
Error: The argument of IsInjective should be a function, but instead it is:
(FALSE :> FALSE @@ TRUE :> FALSE)
Error: The behavior up to this point is:
State 1: <Initial predicate>
x = 0
```

TLC exits with status 255: the error constant 2283
(`TLC_MODULE_ONE_ARGUMENT_ERROR`) is one of the unmapped module constants of
[tlc-002](tlc-002.md). The same module with `Next == UNCHANGED x` and
`INVARIANT Inv` for `Inv == F!IsInjective([a |-> 1, b |-> 2])` fails with the
same message for `[a |-> 1, b |-> 2]` and exits 75.

Variations, `IsInjective` applied to the argument in the first column:

| Argument | Context | TLC |
| --- | --- | --- |
| `[a \|-> 1, b \|-> 2]` | `ASSUME`, invariant | error |
| `[b \in {TRUE, FALSE} \|-> FALSE]` | `(IF _ THEN <<1>> ELSE <<2>>)[1]` in `Next` | error |
| `[b \in {"a"} \|-> 1]` | `(IF _ THEN <<1>> ELSE <<2>>)[1]` in `Next` | error |
| `[b \in 2..3 \|-> 1]` | `(IF _ THEN <<1>> ELSE <<2>>)[1]` in `Next` | error |
| `[b \in {"a"} \|-> 1]` | `<<_>>[1]` in `Next` | error |
| `[b \in 1..2 \|-> 1]` | `(IF _ THEN <<1>> ELSE <<2>>)[1]` in `Next` | `FALSE` |
| `[b \in {"a"} \|-> 1]` | `[i \in {1} \|-> _][1]` in `Next` | `TRUE` |
| `[b \in {TRUE, FALSE} \|-> FALSE]` | `IF _ THEN 1 ELSE 2` in `Next`, `ASSUME` | `FALSE` |
| `<<1, 1>>`, `(FALSE :> 1) @@ (TRUE :> 1)` | `ASSUME` | `FALSE` |

## Cause

From `modules/tlc2/overrides/Functions.java` at CommunityModules `9aae8ea`,
lines 51-74. `IsInjective(Value)` tries, in order: a `TupleValue`; a
`FcnRcdValue` with an interval domain starting at 1; `val.toTuple()`; a
`SetOfRcdsValue`; a `FcnRcdValue`. Anything else throws.

- TLC represents `[a |-> 1, b |-> 2]` as a `RecordValue`, which is none of
  these, so every record is rejected. The comment on the `FcnRcdValue` branch
  names `[a |-> 1, b |-> 2]` as its input. The `SetOfRcdsValue` branch, whose
  comment names `[a: 1, b: 2]`, accepts a set of records, which is not a
  function.
- A function constructor that TLC evaluates lazily is a `FcnLambdaValue`.
  `toTuple()` converts it only if its domain is `1..n`. For any other domain the
  override throws. The `AntiFunction` override in the same file calls
  `normalize().toFcnRcd()` first and accepts both representations.

Whether a constructor reaches the override lazily depends on the surrounding
expression: the variations show that it does inside the function part of an
application `e[i]`, and does not as an `IF` condition or in an `ASSUME`.

## Corpus evidence

The `module` corpus43 run, the first with Community Modules operators, has 212
entries with this diagnostic:

- 39 TLC crashes (exit 255). Three arguments are records, such as
  `[value1_OF_MODEL |-> FALSE, value2_OF_MODEL |-> FALSE]` in `7c447a23`. The
  other 36 are function constructors over non-interval domains, such as
  `(FALSE :> FALSE @@ TRUE :> FALSE)` in `177b83d4`, which the reduction above
  comes from.
- 173 aggregator deviations, where the error occurs while TLC evaluates `Inv`
  and exits 75. Apalache reports a counterexample for 134 of them and passes 39.

`177b83d4` and `f42b02a6` are PBT inputs of generations 24 and 28, not
mutants.

## Expected behavior

The override returns the value of the TLA<sup>+</sup> definition for every
function: it converts its argument with `toFcnRcd()`, as `AntiFunction` does,
and handles `RecordValue`. It no longer accepts a set of records.

## Impact

`Injection`, and through it `Bijection` and `ExistsInjection`, apply
`IsInjective` to functions that `[S -> T]` enumerates. A specification that applies it to a record, or to a
function constructor inside a function application, stops with an error that
blames the argument's type, although the argument is a function.
