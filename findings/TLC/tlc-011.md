# An evaluation error under a bounded `\E` around a temporal formula is reported as "TLC cannot handle the temporal formula"

## Summary

When the domain of a bounded `\E` around a temporal formula fails to evaluate,
TLC reports `TLC cannot handle the temporal formula` (error 2213) and exits 255.
It gives neither the evaluation error nor its location. For
`\E q \in {1} \o <<>> : <>(x = q)`, the spec is incorrect because `{1}` is not a
sequence. TLC's message suggests instead that its liveness translation has no
case for a correct formula. The same happens when a constant-level body of the
`\E` fails, as in `\E q \in {1} : <>(Head(<<>>) = q)`.

The cause is the `OPCODE_be` case of `Liveness.astToLive`. It enumerates the
bound and translates the body inside a `try` that catches every `Exception`. If
the formula's level is temporal, it fails with `TLC_LIVE_CANNOT_HANDLE_FORMULA`
and passes only the formula, not the exception. The `OPCODE_bf` case for `\A`
adds `e.getMessage()` to the report for a `TLCRuntimeException`. For an
`EvalException`, it escapes as error 1000 instead, the class of
[tlc-009](tlc-009.md).

Observed with tla2tools 1.8.0-SNAPSHOT (Maven snapshot
`1.8.0-20260915.155503-70`), the TLC bundled in FuzzTLA on 2026-09-15. The source
cited is `tlaplus/tlaplus` at `8585374d`.

## Reproduction

`FuzzInput.tla`:

```tla
---- MODULE FuzzInput ----
EXTENDS Integers, Sequences
VARIABLE x
Init == x = 0
Next == UNCHANGED x
Spec == Init /\ [][Next]_x
Prop == \E q \in {1} \o <<>> : <>(x = q)
====
```

`FuzzInput.cfg`:

```text
SPECIFICATION Spec
PROPERTY Prop
```

```sh
java -cp tla2tools.jar tlc2.TLC -deadlock -noGenerateSpecTE -config FuzzInput FuzzInput
echo $?
```

```text
Starting... (2026-09-15 20:14:50)
Error: TLC cannot handle the temporal formula line 7, col 9 to line 7, col 40 of module FuzzInput
Finished in 00s at (2026-09-15 20:14:50)
255
```

Replacing `Prop`:

| `Prop` | TLC prints | Exit status |
| --- | --- | ---: |
| `\E q \in {1} \o <<>> : <>(x = q)` | cannot handle, no cause | 255 |
| `\E q \in 1 \div 0 : <>(x = q)` | cannot handle, no cause | 255 |
| `\E q \in {1} : <>(Head(<<>>) = q)` | cannot handle, no cause | 255 |
| `\E q \in {1} \o <<>> : [](x = q)` | cannot handle, no cause | 255 |
| `<>(x = 1) /\ \E q \in {1} \o <<>> : []TRUE` | cannot handle, no cause | 255 |
| `\A q \in {1} \o <<>> : <>(x = q)` | unexpected `EvalException`, `s \o t when s is not a sequence` | 255 |
| `\A q \in {1} : <>(Head(<<>>) = q)` | unexpected `EvalException`, `Head` of the empty sequence | 255 |
| `\E q \in {1} \o <<>> : x = q` | `Evaluating an expression of the form s \o t when s is not a sequence:` with its location | 75 |

The catch also covers a domain that depends on the state, which TLC's liveness
translation does not support
([TLC temporal formula limits](../../conformance/tlc-temporal-formula-limits.md)).
There the evaluation error names the state variable. `\A q \in {x} : <>(x = q)`
reports `cannot handle` followed by "In evaluation, the identifier x is either
undefined or not an operator". `\E q \in {x} : <>(x = q)` reports `cannot handle`
alone, so an unsupported formula and an incorrect one print the same message.

## Corpus evidence

The `module` corpus24 run has one TLC crash with this cause, `c2a07f51`. Its
property is

```tla
Prop ==
  \E q199 \in VariantFilter("Tag240", (VariantGetUnsafe("Tag244", (Variant("Tag242", ""))))):
    SF_FALSE(ENABLED ...)
```

The domain is constant. TLC's `Variants.tla` defines `Variant("Tag242", "")` as
the record `[Tag242 |-> ""]` and `VariantGetUnsafe(tag, v)` as `v[tag]`, so the
domain applies that record outside its domain. Evaluating the same domain in an
invariant reports `In applying the function`. The stored
diagnostic is the bare `Error: TLC cannot handle the temporal formula` line.
Crashes whose domain depends on the state print the same line, so the triager
has no signature for this finding.

## Expected behavior

TLC reports the evaluation error with its diagnostic and location, and a failure
exit status, as it does for `\E q \in {1} \o <<>> : x = q`. "Cannot handle"
should be reserved for formulas that are well defined but outside the liveness
translation.

## Impact

A user whose property has an incorrect quantifier domain is told that TLC does not
support the formula, which suggests rewriting a correct property rather than
fixing an error. Automated consumers classify the run as a checker limitation
and cannot separate it from the documented unsupported shapes.
