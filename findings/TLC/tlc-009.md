# An evaluation error in a constant eventuality escapes as TLC error 1000

## Summary

When a temporal property contains a constant-level eventuality whose evaluation
fails, such as `<>(Head(<<>>) = 1)`, TLC reports "TLC threw an unexpected
exception" before it computes any initial state. `TLC.process()` returns the
general error 1000, and TLC exits with status 255. The same constant predicate
under `[]`, in a state-level property or in an invariant is reported as an
ordinary evaluation error with exit 75.

Observed with tla2tools 1.8.0-SNAPSHOT (Maven snapshot
`1.8.0-20260912.025952-68`). This resembles [tlc-001](tlc-001.md) and
[tlc-003](tlc-003.md), where errors escape as error 1000 from set filters and set
capability checks. Here the error escapes while TLC prepares liveness checking,
independent of the operator that fails.

## Reproduction

`FuzzInput.tla`:

```tla
---- MODULE FuzzInput ----
EXTENDS Integers, Sequences
VARIABLE x
Init == x = 0
Next == UNCHANGED x
Spec == Init /\ [][Next]_x
Prop == <>(Head(<<>>) = 1)
====
```

`FuzzInput.cfg`:

```text
SPECIFICATION Spec
PROPERTY Prop
```

```sh
java -cp tla2tools.jar tlc2.TLC -deadlock -noGenerateSpecTE -config FuzzInput FuzzInput
echo $?
```

```text
Starting... (2026-09-14 12:05:12)
Error: TLC threw an unexpected exception.
This was probably caused by an error in the spec or model.
See the User Output or TLC Console for clues to what happened.
The exception was a tlc2.tool.EvalException
: Attempted to apply Head to the empty sequence.
Finished in 00s at (2026-09-14 12:05:12)
255
```

`TLC.process()` returns 1000 for the same arguments.

| `Prop` | Result |
| --- | --- |
| `<>(Head(<<>>) = 1)` | error 1000, `EvalException` |
| `x = 0 => <>(Head(<<>>) = 1)` | error 1000, `EvalException` |
| `(x = 0) ~> (Head(<<>>) = 1)` | error 1000, `EvalException` |
| `<>(1 \div 0 = 1)` | error 1000, `EvalException` |
| `<>([k \in {1} \|-> k][2] = 1)` | error 1000, `RuntimeException` |
| `[](Head(<<>>) = 1)` | exit 75, reported while computing initial states |
| `Head(<<>>) = 1` | exit 75, reported while computing initial states |

In a 400-module smoke corpus with the `temporal` generator category enabled, two
of the fuzzing workflow's TLC crashes have this shape: one property applies `<>`
to a constant `CHOOSE` without a witness (a `RuntimeException`), and one has a
constant `Head(Head(<<>>))` formula on the left of `~>`. A third error-1000 crash
in the same corpus has a state-level property without temporal operators and is
not covered by this finding.

## Expected behavior

TLC reports the evaluation error with its diagnostic and a failure exit status,
as it does for `[](Head(<<>>) = 1)`.

## Impact

Consumers classify the run as a TLC crash rather than a failing specification.
The message withholds the location of the failing expression, which the
ordinary evaluation-error report includes.
