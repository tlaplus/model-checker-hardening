# The `AntiFunction` override of the Community Modules fails on a non-injective function

## Summary

The Java override of `Functions!AntiFunction` in the TLA+ Community Modules
fails when its argument maps two domain elements to the same value:

```text
Attempted to apply the operator overridden by the Java method
public static tlc2.value.impl.Value tlc2.overrides.Functions.antiFunction(tlc2.value.impl.Value),
but it produced the following error:
The value
1
occurs multiple times in the function domain.
```

The TLA<sup>+</sup> definition is total:

```tla
Inverse(f,S,T) == [t \in T |-> CHOOSE s \in S : t \in Range(f) => f[s] = t]
AntiFunction(f) == Inverse(f, DOMAIN f, Range(f))
```

For a non-injective `f`, the `CHOOSE` has several witnesses and picks one, so
`AntiFunction(<<1, 1>>)` is a function on `{1}`. TLC evaluates
`Inverse(<<1, 1>>, {1, 2}, {1})`, which the definition equates with
`AntiFunction(<<1, 1>>)`, to `<<1>>`. Apalache also evaluates the definition.

Observed with CommunityModules release `202609120237` (commit `9aae8ea`), tla2tools
1.8.0-SNAPSHOT (Maven snapshot `1.8.0-20260917.033119-76`, tlaplus/tlaplus
commit `142d0ba`), FuzzTLA `a13a4d1`, and Apalache 0.62.2 (build `f0dec98`).

## Reproduction

`FuzzInput.tla`, run with `CommunityModules.jar` on the class path:

```tla
---- MODULE FuzzInput ----
EXTENDS Naturals
F == INSTANCE Functions
VARIABLE x
Init == x = 0
Next == UNCHANGED x
Spec == Init /\ [][Next]_x
Inv == F!AntiFunction(<<1, 1>>) = F!Inverse(<<1, 1>>, {1, 2}, {1})
====
```

`FuzzInput.cfg`:

```text
SPECIFICATION Spec
INVARIANT Inv
```

```sh
java -cp tla2tools.jar:CommunityModules.jar tlc2.TLC \
  -workers 1 -deadlock -noGenerateSpecTE -config FuzzInput FuzzInput
```

TLC prints the error above and exits 75. With
`Inv == F!Inverse(<<1, 1>>, {1, 2}, {1}) = <<1>>`, which does not call the
override, TLC reports no error and exits 0.

For Apalache, with `x` typed `Int`,
`Inv == LET g == AntiFunction([i \in {1, 2} |-> 1]) IN DOMAIN g = {1} /\ g[1] \in {1, 2}`
holds (`apalache-mc check --length=0 --inv=Inv`, exit 0).

## Cause

From `modules/tlc2/overrides/Functions.java` at CommunityModules `9aae8ea`,
lines 103-120. `antiFunction` quotes the definition in a comment, converts its
argument with `normalize().toFcnRcd()`, and returns
`new FcnRcdValue(domain, range, false).normalize()`, where `domain` is a copy
of the argument's values and `range` its domain. Building this value rejects a
domain array with duplicates, which is the message above; the exact frame was
not traced. For an
injective argument the result is the definition's value; for any other
argument the override has no `CHOOSE` counterpart.

## Corpus evidence

The `module` corpus43 run has 428 entries with this diagnostic:

- 1 TLC crash, `3914df96`. The application is in a temporal property and is
  evaluated before the initial states. TLC reports it under
  `TLC_MODULE_VALUE_JAVA_METHOD_OVERRIDE` (2154), which exits 255, see
  [tlc-002](tlc-002.md).
- 427 aggregator deviations, where TLC exits 75. The stored first line of the
  TLC diagnostic is `The value`; a rerun of `0051805f`, `012c6491`,
  `02a570ec` and `01433fbe` gave the override error above for each, with
  duplicated values such as `<<FALSE, FALSE, FALSE>>` and
  `{<<FALSE>>, <<TRUE>>}`. Apalache reports a counterexample for 223 of them and
  passes 204.

`3914df96` and `0051805f` are PBT inputs of generations 6 and 3, not mutants.

## Expected behavior

The override returns a value of the definition for every function, for example
by keeping the first domain element for each duplicated value. If upstream
intends `AntiFunction` only for injective functions, the TLA<sup>+</sup>
definition and its comment should say so; the operator then has no defined
value, like `CHOOSE` without a witness, and the current error is a diagnostic
for that.

## Impact

A specification that inverts a function that is not injective stops with an
error in TLC, while the same specification checks in Apalache. The error names
a Java method and a function domain, not the precondition that the user
violated.
